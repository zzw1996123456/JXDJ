# 景序电竞三角洲趣味

一个可以免费部署的三角洲趣味单平台。主页用于选择不同玩法，目前首个可用趣味单为“护航大富翁”，支持管理员创建房间、自动生成随机棋盘、逐格编辑规则、玩家凭房间码加入、1–10 轮行动和护航条款结算。

未配置 Supabase 时仍可使用“本机试玩”完整体验大富翁，但在线房间需要完成下面的 Supabase 配置。

## 本地运行

需要 Node.js 20 或更高版本。

```powershell
npm install
npm run dev
```

浏览器打开终端显示的地址，通常是 `http://localhost:5173`。

## 第一步：创建免费 Supabase 后端

1. 打开 [Supabase](https://supabase.com/) 并登录。
2. 点击 `New project`，创建一个免费项目，并妥善保存数据库密码。
3. 项目初始化完成后，打开左侧 `SQL Editor`。
4. 点击 `New query`，粘贴 [supabase/schema.sql](./supabase/schema.sql) 的全部内容。
5. 点击 `Run`。看到 `Success` 后，数据表、权限和游戏函数就创建完成了。
6. 打开 `Authentication` → `Providers` → `Anonymous Sign-Ins`，启用匿名登录并保存。

匿名登录只用于区分普通玩家，不会要求玩家填写邮箱和密码。管理员使用单独的邮箱和密码登录。

### 创建管理员账号

1. 在 Supabase 左侧打开 `Authentication` → `Users`。
2. 点击 `Add user` → `Create new user`。
3. 输入你自己的管理员邮箱和密码，并确认创建。
4. 回到 `SQL Editor`，新建一条查询，粘贴下面的内容。
5. 把示例邮箱替换成刚才创建账号时使用的真实邮箱，然后点击 `Run`。

```sql
insert into public.app_admins(user_id)
select id from auth.users
where email = '你的管理员邮箱'
on conflict (user_id) do nothing;
```

看到 `Success` 后，该账号才能进入网站的“管理员入口”。管理员不占房间的 3 个玩家名额。

## 第二步：取得环境变量

在 Supabase 项目中打开 `Project Settings` → `API Keys`，找到：

- `Project URL`
- `Publishable key`（旧版界面可能显示为 `anon public` key）

在项目根目录复制一份 `.env.example`，命名为 `.env.local`，填入真实值：

```env
VITE_SUPABASE_URL=https://你的项目编号.supabase.co
VITE_SUPABASE_ANON_KEY=你的公开匿名密钥
```

不要把 `.env.local` 提交到 Git。Supabase 的 publishable/anon key 可以放在前端，但绝不能把 `service_role` 或 secret key 放进网页或 Vercel。

完成后重新运行：

```powershell
npm run dev
```

大富翁入口显示“在线房间”即代表配置已生效。测试时先从“管理员入口”创建房间，再使用普通窗口和无痕窗口分别以玩家身份加入同一个房间。

## 第四步：免费部署到 Vercel

1. 打开 [Vercel](https://vercel.com/) 并使用 GitHub 登录。
2. 点击 `Add New...` → `Project`。
3. 选择 `JXDJ` 仓库并点击 `Import`。
4. Framework Preset 保持 `Vite`，构建命令保持 `npm run build`，输出目录保持 `dist`。
5. 展开 `Environment Variables`，添加：
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
6. 点击 `Deploy`。

部署完成后会得到类似 `https://你的项目名.vercel.app` 的免费网址。把网址发给其他玩家，他们不需要安装任何软件。

## 当前大富翁规则

- 每间在线房最多 3 人，固定为 1 个老板席和最多 2 个打手席。
- 只有管理员可以创建、开始和手动结束房间；管理员可以查看每个房间的玩家与完整掷骰记录。
- 在线房至少需要 1 名老板和 1 名打手，所有玩家准备后，管理员才能开始；本机试玩允许单人直接体验。
- 默认三轮分别为 8、12、24 格；管理员可配置 1–10 轮，每轮为 2–100 之间的偶数格。
- 第一轮使用轻量规则池，第二轮扩大移动和骰子效果范围，第 3–10 轮复用第三轮的完整规则池。
- 每个非最终轮至少保留一个进入下一轮的格子，只有当前配置的最终轮保留结束格。移动格只改变最终位置，不会连续触发目标位置的第二个效果，避免规则循环。
- 棋盘格保持固定尺寸并使用更宽松的格间距，2–24 格使用经典环形棋盘，26–100 格自动增加同心路线环；棋盘中央不再显示额外面板，完整空间可用于地图排布和路线观察。后台和玩家端都可拖拽地图，并通过滚轮或工具按钮在 10%–200% 范围内缩放、恢复 100% 或适应视图。棋盘内滚轮只控制地图缩放，不会带动外层页面滚动。
- 棋盘采用有向路线图和无限画布：管理员可无边界平移视图，并把任意格子拖到像素级位置（支持负坐标、重叠且不吸附网格）。选择一个格子后可围绕它原子新增两格，系统会保持序号与默认路线连续；也可添加或删除单向/双向路线。每格最多 4 个出口；开局前系统会拒绝存在无出口格子的棋盘。
- 后台提供 5 种自适应地图排布：同心封锁、补给长廊、中心突围、菱形战区和三线推进。所有预设均支持每轮 2–100 格，格子越多会自动增加环数、折返段、包围层或推进区段；应用后可立即撤销回原排布。
- 所有房间共用同一个格子图片库，同一张图片可被任意房间、任意数量的格子复用。管理员上传前先拖拽选择裁剪区域并在真实格子比例中预览；浏览器只上传裁剪后的 WebP，自动压缩到 15 KB 以内，不会把原图存入服务器。删除公共图片会同步清除所有房间格子的引用。
- 老板和打手都按箭头移动。一次掷骰存在多条合法路径时，回合会暂停并由当前玩家选择完整走向；选定后才结算终点格效果并轮换玩家。旧房间会自动补成原有的单向闭环路线。
- 玩家掷骰后会沿实际路线逐格移动，每经过一格都有格子高亮、能量环和棋子跳跃反馈；移动播放期间会锁定重复掷骰与路线选择。界面采用统一的深色毛玻璃、动态流光、路线能量和游戏化状态动效，并为手机棋盘自动适配完整视图。
- 管理员可分别设置每次轮次转换的“每次掷骰晋级概率”。只有老板具备晋级资格，并且老板在每一轮自己的前 2 次掷骰都处于保护期；从该轮第 3 次开始才按概率独立判定。打手无论掷多少次都不会触发晋级。
- 概率设为 0% 时绝不会落到进入下一轮格，设为 10% 时每次掷骰均有独立的 10% 概率落到进入下一轮格。只有实际落在进入下一轮格时才会晋级，其他格绝不会触发晋级。
- 每次落格只结算一种实际效果；移动格只移动位置，不会结算移动后所在格的效果。
- 每位玩家都有独立且可见的骰子库存，每次掷骰永久消耗 1 个，并立即轮到下一位仍有骰子的玩家。管理员可在 0–20 个范围内为任意玩家增加或减少骰子；骰子变成 0 时自动跳过且保持为 0，只有管理员补充后才能再次行动。全员均为 0 时，本局等待管理员补充骰子。
- 只有老板拥有保底，单位为“万”。管理员可在开局前设置基础保底，也可在房间玩家列表中直接输入老板当前保底。
- 保底格支持增加、减少、乘倍和除倍四种结算；管理员可在格子编辑器中手动输入保底变化数值，加减支持 1–100000 万的整数，乘除支持 0–10 倍且可输入小数。格子名称与说明会自动更新；乘除结果四舍五入取整，除数为 0 时按 0 万结算。任何玩家触发时都结算到老板，打手不拥有保底，保底最低为 0。
- 最终轮有人触发结束格时自动结算；管理员也可以手动结束本局。
- 玩家退出房间页面或关闭网页时会保留原席位；再次输入同一房间码和原行动代号，即可恢复原身份、位置、回合状态并继续游戏。
- 同一房间内的行动代号不能重复。行动代号是重新进入席位的验证信息，请玩家记住自己当前保存的行动代号。
- 在管理员开始房间前，玩家可以修改自己的行动代号和老板/打手身份；切换为老板时会自动将原老板调整为打手。修改后需要重新准备，开局后不能再修改。
- 每次全员骰子数量归零时，系统会自动生成一条归零规则：去重汇总从开局到当次归零为止打手触发的全部持续遵守规则，并记录老板当时保底。管理员可为每条规则补充最多 200 字的后缀；补充骰子后再次归零会生成新规则。
- 管理员可以暂停进行中的房间。暂停会锁定所有掷骰并阻止玩家进入或重新进入；继续后保留原轮次、当前玩家和剩余骰子，玩家可重新进入接着玩。
- 掷骰、移动、暂停、额外次数和老板保底均在数据库函数中计算，浏览器不能直接修改游戏结果。

升级已有部署时也需要在 Supabase SQL Editor 中重新执行完整的 `supabase/schema.sql`。本次升级会新增连续坐标、公共图片库、完整配置导入、配置收藏和“双余额保底申请”所需的数据表、Realtime、Storage 权限及后台接口，并自动兼容旧房间网格坐标；只部署前端会导致无限画布、图片上传、完整导入、收藏和保底审批无法保存。保底申请会在老板确认时按“现有保底优先、基础保底补足”在同一事务内扣减。

## 管理员创建房间流程

1. 进入“管理员入口”，使用已加入白名单的邮箱和密码登录。
2. 输入 1–24 个字符的房间名，再点击“创建”。默认生成 8、12、24 格的三轮棋盘，每轮第 1 格是固定起点。开局前可将轮数调整为 1–10 轮，并将每轮格子数独立调整为 2–100 之间的偶数。
3. 玩家凭 6 位房间码加入后，在“回合设置”中选择谁先掷骰，并设置每位玩家开局拥有的 1–5 个初始骰子。
4. 需要换一套棋盘时点击“重新随机全部轮次”。普通房间会随机所有非起点格；导入设置的房间只替换标记为“重新随机时替换此格”的位置，其他格子和所有自定义颜色保持不变。
5. 需要快速改变地图结构时，先切换轮次，再选择 5 种地图排布预设之一；预设会按当前格子数自动生成坐标，并可用“撤销预设”恢复。需要精调时可在无限画布中自由拖动，或选择某个格子围绕它新增两格、修改内容和颜色，并从所有房间共用的图片库选择可复用图片。
6. 后端会限制每轮可用效果的范围，并强制非最终轮保留晋级格、最终轮保留结束格。
7. 管理员可在玩家列表中修改任意玩家的老板/打手身份。局中更换老板时会保留当前保底，且始终只保留一名老板。骰子和老板保底都可直接输入数字后保存；骰子允许 0–20 个，等待阶段的保底允许 0–10000 万。
8. 所有玩家准备后点击“开始房间”。开局后棋盘和回合配置会锁定，普通玩家不能再修改自己的行动代号或身份；管理员仍可修改玩家身份、查看实时记录、直接设置骰子与老板当前保底、暂停/继续或手动结束。
9. 暂停后所有玩家会退出本局且无法重新进入；点击“继续本局”后，玩家使用原房间码和行动代号即可接着玩。
10. 管理面板顶部的“清理缓存”会清除当前浏览器保存的房间信息与 Cache Storage、重新读取管理数据，并通知 Supabase 重新加载后端接口结构缓存；管理员登录状态不会被清除。
11. 不再需要的房间可以在房间详情右上角删除。确认后会同时清理该房间的玩家、棋盘和行动记录，无法恢复。
12. “房间配置”下拉菜单提供完整导出、完整导入和收藏当前配置。版本 6 JSON 会自包含房间名、开局数值、晋级概率、轮数、每轮格子数、全部格子内容与颜色、随机标记、无限画布坐标、路线以及房间实际使用的压缩图片；不包含房间码、玩家、先手玩家或任何对局记录。完整导入只能用于等待中房间，并会在一个数据库事务中替换以上配置而不删除当前玩家席位；版本 1–5 的旧文件仍可导入。
13. 收藏保存在当前管理员账号下，可删除，并可从左侧“配置收藏”直接创建完整配置的新房间。创建前填写房间名称会采用该名称，留空则自动使用“收藏名 副本”；图片会复用所有房间共用的公共图片库，缺失图片则从收藏中的 15 KB 以内 WebP 数据恢复。
14. 房间结束后，“导出记录”会下载 UTF-8 TXT，完整列出每次摇骰的时间、玩家、身份、轮次、点数、落格和说明，并附带所有归零规则及手动后缀。

如果 Supabase 项目已经初始化过，更新到本规则后需要再次在 `SQL Editor` 中完整执行 [supabase/schema.sql](./supabase/schema.sql)。脚本可以重复执行，会更新数据表、权限与游戏函数，不需要删除已有项目。执行完成后，还要按照上面的“创建管理员账号”步骤把管理员加入白名单。

升级数据库结构后，已有房间的每轮第 1 格会自动转换为起点。已经进行中的旧房间可继续完成；需要使用可配置轮数、格子数和导入定向随机时，请新建或在等待中的房间操作。

## 常见问题

### 大富翁入口显示“本机试玩”而不是“在线房间”

确认环境变量名称完全一致，并在修改 `.env.local` 后重启开发服务器。Vercel 中修改环境变量后需要重新部署。

### 加入房间时报匿名登录错误

进入 Supabase 的 `Authentication` → `Providers`，确认 `Anonymous Sign-Ins` 已启用。

### 管理员登录后提示“不在管理员白名单”

确认你已经在 `Authentication` → `Users` 创建了邮箱账号，并在 `SQL Editor` 执行过“创建管理员账号”章节中的 SQL。SQL 中的邮箱必须与登录邮箱完全一致。

### 两个窗口被识别成同一个玩家

同一浏览器的普通标签页会共享匿名登录状态。联机测试时请使用不同浏览器，或一个普通窗口加一个无痕窗口。

### 怎样清空现有房间和玩家数据

在 Supabase 的 `SQL Editor` 执行下面的 SQL。删除全部房间时，每个房间的玩家席位、棋盘和行动记录会一起永久删除，管理员白名单和全局格子规则会保留。

```sql
begin;
delete from public.rooms;
commit;
```

普通玩家使用 Supabase 匿名登录，所以删除房间后，`Authentication > Users` 里的匿名账号仍会保留。如果这些测试账号也需要清空，在上面的 SQL 成功执行后再执行：

```sql
delete from auth.users as users
where users.is_anonymous is true
  and not exists (
    select 1 from public.app_admins as admins where admins.user_id = users.id
  );
```

这段 SQL 只删除匿名账号，不删除邮箱管理员。已经打开网站的普通玩家需要刷新页面，Supabase 会为他创建新的匿名身份。两种删除都无法恢复。

### 国内访问速度不稳定

Vercel 和 Supabase 的免费节点通常位于境外，适合原型测试，但中国大陆访问质量无法保证。正式面向大量国内用户时，需要迁移到有备案条件的国内云服务。
